# 沙箱账号准备

2026-11-14，G包。当前完成的是本地适配代码与测试；真实接口联调待本人提供账号，不能据此认定真实收付款或正式物流已接通。

## 先了解使用范围

支付宝选手机网站支付，服务端用Node内置crypto生成RSA2签名，原生独立ArkWeb打开固定沙箱网关。页面明确显示“沙箱测试，不会真实扣款”。网页返回和关闭都不判成功，由服务端主动查单确认。没有新增SDK或第三方依赖。

支付宝沙箱App不支持模拟器，官方也说明鸿蒙默认浏览器不能唤起沙箱App。因此Pura 90 API24能否完成网页付款尚待账号实测；当前组件只允许支付宝HTTPS页面，拦截自定义协议唤端。若渠道要求唤端，本机模拟器闭环即受阻，不新建或串用模拟器，不绕过平台限制。

本包不提供沙箱账单对账：官方说明沙箱账单仅为模板，不能把本地订单当成渠道账单。独立运费补偿也未接入支付宝资金渠道，不能用超额退款替代。

## 本人准备支付宝账号

1. 在支付宝开放平台 https://open.alipay.com 本人登录、完成开发者入驻；沙箱入口为 https://open.alipay.com/develop/sandbox/app 。不需要在本任务中申请真实商户或购买服务。
2. 选择沙箱应用，核对手机网站支付产品是否可用，记录沙箱APPID和沙箱卖家UID。卖家UID不是沙箱买家的手机号或账号。
3. 依控制台RSA2配置生成或保存应用私钥及应用公钥；把应用公钥配置到沙箱平台，从平台取回对应支付宝公钥。服务端只需应用私钥、支付宝公钥；不能把应用公钥错当支付宝公钥。
4. 密钥至少RSA2048，保存完整PEM，包括BEGIN/END行。控制台若只给Base64正文，按其标注的PKCS格式导出PEM，不猜测格式。私钥由本人保存，勿贴入聊天、日志、截图或仓库。
5. 获取沙箱买家账号用于收银台；只在沙箱页面输入，不写入服务器示例文件。应用账号的付款人和渠道沙箱买家是两套身份；退款仍针对原支付宝交易，不能通过更换应用账号指定退款去向。

## 本人确认快递鸟权益

1. 进入 https://www.kdniao.com ，本人注册/登录开发者控制台，查看“即时查询”RequestType=1002权限。
2. 核对个人身份是否可用、免费次数、支持承运商、有效期、用途限制及是否需要额外开通。公开介绍中的“100次”和技术页的接口上限不能替代本人账号权益，当前只把快递鸟列为候选；若没有个人免费权限，先保留mock物流，不购买套餐。
3. 确认后由本人保存EBusinessID与AppKey，并准备本人有权查询的真实运单。顺丰等要求附加手机号信息的接口场景尚未适配，优先用控制台明确支持且不要求附加校验信息的承运商验证，不能伪造轨迹。
4. 当前内置承运商映射包括顺丰、中通、圆通、申通、韵达、京东、邮政、EMS、极兔和德邦；也可填写平台的大写承运商编码，能否查询以账号权限及服务响应为准。

## 填写仓库外配置

1. 在本人用户目录新建 `.hdm-sandbox` 文件夹，将 `server/.env.sandbox.example` 复制为其中的 `server.env`；该文件和PEM均不要放回仓库。示例只包含变量名与说明，空值不是可直接启动的配置。
2. 填 `NODE_ENV=development`、`PAYMENT_CHANNEL=alipay-sandbox`、`MOCK_PAYMENTS=false`；物流权益未确认时填 `LOGISTICS_CHANNEL=mock`，确认后才改为`kdniao`。
3. 本机常规服务可填 `HOST=127.0.0.1`、`PORT=3000`、`PUBLIC_URL=http://127.0.0.1:3000`；设备访问和端口映射沿现有受控流程执行，不占用回归夹具3103。填写独立的仓库外 `DATABASE_PATH` 与 `UPLOADS_PATH`；切换渠道时不要复用已有mock交易库。
4. CORS按当前客户端配置显式填写；打包H5需要时包含`null`，不使用通配符。
5. 填APPID和卖家UID；私钥和公钥优先填写 `ALIPAY_PRIVATE_KEY_FILE`、`ALIPAY_PUBLIC_KEY_FILE` 的绝对路径，每组直接值与文件变量只能选一个。APPID、卖家UID、快递鸟ID和AppKey也支持相应`_FILE`。缺少内容、读文件失败或密钥无效会在启动时报字段名，不输出值。
6. 本机没有公网HTTPS回调时把 `ALIPAY_NOTIFY_URL` 留空，以主动查单验收。不要把localhost或模拟器地址填成异步通知地址，不自行部署公网服务或开启隧道。以后经授权使用公网HTTPS时，路径须为`/payments/alipay/notify`。
7. 本人需要初始化商家时填写 `MERCHANT_ACCOUNT`、`MERCHANT_PASSWORD`，不要复用或回传真实生活账号密码。

在 `D:\hdm-mall\server` 下启动，命令只含文件路径，不含密钥：

```powershell
node --env-file="$env:USERPROFILE\.hdm-sandbox\server.env" src/main.ts
```

固定网关为 `https://openapi-sandbox.dl.alipaydev.com/gateway.do`，不能通过配置换成正式网关；production会拒绝沙箱。公钥、私钥、卖家和应用必须属于同一个沙箱配置。

## 有账号后的验收顺序

本人下单 → 原生确认付款 → 沙箱买家付款 → 关闭并核对付款结果 → 服务端查单确认 → 走既有取消/售后退款路径 → 退款或退款查询确认 → 查看有权查询的快递轨迹。保留脱敏状态、时间和渠道编号，不能保存签名收银台URL、密钥或账号凭据。

未付款时可从订单重新进入收银页，点击“继续沙箱付款”；服务端只对仍有权限的原付款人返回原支付单收银台，不新增支付单、不延长十分钟宽限期。换账号、离页或旧响应到达均不得打开旧收银台。超时、已付、取消或人工核实时不能续开。

查单失败或签名不正确仍为待确认；未打开的WAP订单可能尚未在支付宝创建，查无交易不被当作“已关单”，超过核实窗口沿既有人工核实流程处理。退款未知沿现有重试处理，不据客户端提示推断成功。

物流以渠道事件时间排序，重复不新增、状态只进不退，签收不自动确认收货；30分钟内同一运单复用查询结果以减少额度消耗。沿用现有时间校验：事件不得早于商家发货登记时间或晚于服务端时间，若真实记录不满足条件应报告差异，不改时间伪造通过。
