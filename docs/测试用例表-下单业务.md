# 惠多美商城（hdm-mall）下单业务测试用例表

> 依据《纯血鸿蒙APP测试》思维导图测试方法 + 项目说明.txt 风险区（SKU 兜底展示与交易边界校验、按登录账号隔离的本地收藏与浏览足迹）整理。
> 主流程链路：LoginView → SearchView → SearchResultView → GoodsView(详情) → CartView → CheckView → PayView → PayResultView → OrderView → MineView

## 一、主流程（登录 → 搜索 → 详情 → 购物车 → 支付 → 订单）

| 编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| TC-001 | 正常登录 | 已注册账号，网络正常 | 1.进入"我的"；2.输入正确账号密码；3.点登录 | 登录成功，跳转个人中心，显示头像昵称 | P0 |
| TC-002 | 密码错误登录 | 已注册账号 | 1.输入正确账号+错误密码；2.点登录 | 登录失败，toast 提示"账号或密码错误"，不跳转 | P0 |
| TC-003 | 未登录加购拦截 | 未登录状态 | 1.搜索商品进详情；2.点"加入购物车" | 弹出登录引导/跳转登录页，不产生购物车数据 | P0 |
| TC-004 | 汉字搜索命中 | 后台上架 5 个"牙膏"商品 | 1.首页点搜索框；2.输入"牙膏" | 输入"牙"出现自动补全（牙膏/牙刷…），完整输入后 5 条商品按 UI 效果展示 | P0 |
| TC-005 | 空关键词搜索 | 已进入搜索页 | 1.进搜索页；2.不输入内容直接触发搜索 | 不发起搜索请求，继续停留在搜索页 | P1 |
| TC-006 | 详情页展示一致性 | 商品数据正常 | 1.从搜索结果点进商品详情 | 标题/价格/主图/规格与后台数据一致，无错位、无串数据 | P0 |
| TC-007 | 正常加购 | 已登录，商品有库存 | 1.详情选 SKU；2.设数量 1；3.点加购 | toast 提示成功，购物车角标 +1，购物车内商品/规格/价格正确 | P0 |
| TC-008 | 修改购买数量 | 购物车已有商品 | 1.进购物车；2.点"+"到库存上限/点"-"到 1 | 数量实时变化，小计金额同步刷新，不能减到 0 或负数 | P0 |
| TC-009 | 勾选结算 | 购物车有 2 个商品，勾选其一 | 1.勾选 1 件；2.点"去结算" | 仅勾选商品进入结算页，合计金额=勾选商品小计之和 | P0 |
| TC-010 | 正常支付成功 | 结算页有订单，支付渠道可用 | 1.确认地址/金额；2.点提交订单；3.完成支付 | 支付成功页展示，订单状态变为"已支付/待发货"，金额与结算页一致 | P0 |
| TC-011 | 支付中断/取消 | 结算页已提交订单 | 1.提交订单；2.支付页点返回/取消 | 订单生成且状态为"待支付"，重新进订单可继续支付 | P1 |
| TC-012 | 我的订单查看 | 已有已支付+待支付订单 | 1.我的→我的订单；2.切换 Tab | 各状态订单归到对应 Tab，数据与支付结果一致 | P0 |
| TC-013 | 个人中心/H5 头像同步 | 已登录，ArkWeb 页面可打开 | 1.原生端修改头像；2.进入 H5 页面查看 | H5 端（Vue3）同步显示新头像，无残留旧图 | P1 |

## 二、重点组 A：SKU 边界 + 交易边界（对应"SKU 兜底展示与交易边界校验"）

> 测试对象：HDMSku 组件、GoodsDetail、下单/结算接口

| 编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| SKU-01 | 规格正常联动 | 商品有多规格多库存 | 依次选择不同颜色/尺码 | 价格、库存、主图随选中 SKU 实时联动刷新 | P0 |
| SKU-02 | 未选完整规格购买 | 商品有 2 个以上规格维度 | 只选"颜色"不选"尺码"→点加购/立即购买 | 按钮置灰或 toast 提示"请选择完整规格"，不发起下单请求 | P0 |
| SKU-03 | SKU 售罄 | 某规格库存=0 | 选择该售罄规格 | 展示"售罄/缺货"兜底样式，按钮不可点击或点击提示无货 | P0 |
| SKU-04 | SKU 数据异常兜底 | 接口返回 SKU 数据缺失（价格为空、规格列表空） | 打开该商品详情 | 展示默认兜底图/默认文案，页面不白屏、App 不崩溃 | P0 |
| SKU-05 | 数量输入 0 | 详情/购物车数量可输入 | 手动输入 0 | 拦截，恢复为最小值 1，并提示最小购买量 | P0 |
| SKU-06 | 数量输入负数/非法字符 | 同上 | 输入 -1、abc、1.5 | 拦截非法输入，恢复合法值，无崩溃 | P0 |
| SKU-07 | 数量=库存上限 | 商品库存为 N（如 99） | 点"+"加到 N | 可加到 N 并正常下单，按钮到上限后禁用 | P0 |
| SKU-08 | 数量超过库存 | 同上 | 点"+"到 N+1 或手动输入 N+1 | 提示"库存不足/超出库存"，不能下单 | P0 |
| SKU-09 | 数量超大值 | 同上 | 手动输入 999999 | 有上限拦截（限购值或库存值），不发出异常请求 | P1 |
| SKU-10 | 切换 SKU 价格联动 | 不同 SKU 价格不同 | 加购 A 规格→返回→换 B 规格→加购 | 购物车两条记录价格各自正确，结算合计正确 | P0 |
| SKU-11 | 快速切换后立即下单 | 多规格商品 | 快速连续点选规格，立即点"立即购买" | 下单的是最后选中的 SKU（防止竞态导致下单旧 SKU） | P0 |
| SKU-12 | 已下架商品 | 商品被后台下架 | 从历史足迹/收藏/旧分享链接进入详情 | 提示"商品已下架"，不可加购不可下单 | P1 |

## 三、重点组 B：多账号数据隔离（对应"按登录账号隔离的本地收藏与浏览足迹"）

> 测试对象：Auth / UserSession / LocalGoodsStore / AuthCart（本地持久化 + 账号维度隔离）

| 编号 | 用例名称 | 前置条件 | 测试步骤 | 预期结果 | 优先级 |
|---|---|---|---|---|---|
| ISO-01 | 账号 A 收藏可见 | 账号 A、B 均可登录 | A 登录→收藏商品 X→查看收藏列表 | A 的收藏列表中有 X | P0 |
| ISO-02 | B 看不到 A 的收藏 | A 已收藏 X 并退出 | 退出 A→登录 B→打开收藏列表 | B 的收藏列表为空（或只有 B 自己的），不含 X | P0 |
| ISO-03 | 浏览足迹隔离 | A 浏览过商品 Y 并退出 | 登录 B→打开浏览足迹 | B 的足迹不含 Y | P0 |
| ISO-04 | 购物车按账号隔离 | A 加购商品 M 并退出 | 登录 B→打开购物车 | B 的购物车为空/仅含 B 自己的商品，不含 M | P0 |
| ISO-05 | 未登录态访问 | 未登录 | 未登录打开收藏/足迹/购物车 | 空态页或提示"请先登录"，不展示任何账号残留数据 | P0 |
| ISO-06 | 重新登录数据保留 | A 之前收藏了 X | A 退出→A 重新登录→看收藏 | X 仍在（本地数据按 A 持久化，未丢失） | P0 |
| ISO-07 | 快速切换无串写 | A、B 两账号 | A 登录→立即退出→立即登录 B（连续快速操作） | 收藏/足迹/购物车全部为 B 的数据，无 A 残留（时序边界） | P0 |
| ISO-08 | 清除应用数据 | 任一账号已登录且有本地数据 | 设置中清除应用数据/卸载重装 | 本地收藏、足迹、购物车清空，登录态失效回到未登录 | P1 |
| ISO-09 | H5 头像资料同步 | 已登录 | 原生改头像/昵称→打开 H5 个人页 | H5 与原生显示一致（ArkWeb 双向通信正确） | P1 |
| ISO-10 | 多端同账号策略 | 同账号在不同设备登录（可选） | 设备 1 收藏→设备 2 查看 | 与需求约定一致（本地隔离方案通常不同步，需与开发确认预期） | P2 |

## 四、执行说明

- P0 用例每次版本必跑；P1 冒烟后跑；P2 视需求。
- `hdm_uitest/` 是 DevEco Testing Hypium 场景清单；没有固定后端夹具或真实支付环境的 SKU/支付场景标记为手工验收，不能仅凭场景脚本判定通过。
- 原生业务单元测试使用 `hvigorw test --mode module` 编译/生成报告；UiTest 仍需真机或模拟器执行。
- 控件定位以 UIViewer 实际抓取为准，占位定位在 `hdm_uitest/pages.py` 中修正。
- 包名确认方式：`hdc shell bm dump -n <包名>`，或 DevEco Studio 的 AppScope/app.json5 中查看 bundleName。
