## 尺码如何进入订单

字段目录从 promises-20261118-2 升至 promises-20261120-3。服饰、鞋靴新增 size-chart 和 fit，两个字段的 suggestedAfterSaleKind 均为 null。箱包返回不适用。10 个以上既有通用及品类字段仍走各自的规则。

尺码表把一段连续原文同时作为 value 与 quote，用 sourceRef 的起止位置和版本保留全部数字、单位及换行。商家一次确认一张表，每个订单项用原有交易过程冻结这一条。这样保留了表头共用单位和多行对应关系，也能用相同的原文定位检查一个数字的改动。程序核查行格式，不生成、换算或补齐尺寸。支持常见的尺寸行以及“尺码 胸围(cm) 衣长(cm)”这类带单位的表头；无法识别的格式留作未知。

版型用 value 保存逐字片段，用 fit 单独保存偏大、偏小或标准。例如“本鞋为正常尺码”保存 value 为“正常尺码”、fit 为“标准”。完整原句、建议、限制提醒和来源随草稿进入发布回执及订单快照。缺乏明确版型、来源有冲突、否定、疑问或推测时保持未知。历史订单按下单时的版本读取，1、2 两版都有共同向量，没有回填操作。

商品详情根据实际品类展示表格、三个版型及选中标识；没有已发布版型时显示“商家未说明版型”。商家仍需逐项确认，买家从订单核对点“尺码与承诺不符”可进入原售后页。手机入口没有改动。

## 两种退货原因

迁移 023 在 after_sales 增加可空的 size_reason，旧记录保留空值。买家直接申请时可以选“个人穿着不合适”，保存 personal-fit。若通过尺码表或版型核对申请，服务端在申请事务里核对同一 SKU 的冻结字段和不符记录，保存 size-promise-mismatch 并关联原核对记录、发布回执和冻结原文。客户端不能自行声明第二种原因。两者都不改变售后资格、时限或售后类型。买家与商家可在案件详情看原因，GET /merchant/after-sales 可用 sizeReason 分开查询。备份和恢复同时核对原因、申请回执和承诺引用。
