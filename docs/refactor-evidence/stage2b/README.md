## 改动

- `server/src/migrations/022-source-records.sql` 增加商品批次、材料版本和订单材料引用表。材料附件直接保存在数据库，随数据库备份一起校验和恢复。
- `server/src/source-verification/` 负责店主归属、版本追加、批次、有效期、附件权限、材料摘要脱敏及备份完整性检查。上传需要当前店主身份和该商品的创建者。
- 上传资料包含材料类型、适用商品和批次、有效期起止、公开摘要、上传人及当时身份、上传时间、SHA-256 和版本。摘要会隐藏常见电话、证件号码、邮箱、网址和有明确标签的个人字段。
- 承诺抽取只读取当前商品批次、有效期内、未撤销且最新的商家填写摘要。材料引用保留材料编号、版本和摘要文字位置，草稿确认和发布前会再次检查材料未变更。
- 买家商品详情和订单承诺卡片显示来源摘要、材料版本、批次、有效期、下单时核验状态及当前状态。订单引用和状态在下单时冻结，材料更新不会改写旧订单。店主原件接口只接受该商品的店主身份，不向买家开放。
- 所有材料默认处于 `商家提供 / 待核验`。本阶段没有可标记“已按所列依据核验”的入口，任意当前身份提交核验请求都会因路由不存在被拒。共享契约也要求核验人、时间和依据同时存在，数据库完整性检查再校验同一条件。AI 只提取文字承诺，不能改核验状态。
- 买家提示改为“原文另有适用限制，以原文为准”；商家草稿页继续显示“请看原文核对”。买家页面没有暴露内部字段名或附件摘要哈希。

## 状态说明

材料的核验状态仅允许商家提供、待核验、已按所列依据核验、无法核验；有效性另按适用、尚未生效、已失效、已撤销或批次不匹配显示。过期和批次不匹配不会转成有效材料，也不会变成正面承诺。下单状态与当前有效性分开保存。

本阶段允许的数据层表示“已按所列依据核验”，用于共享协议和数据库约束；没有提供设置状态的服务或界面路径。真实的合格核验人及权威渠道留待后续阶段。
