# 阶段 3A 收货后逐条评价

任务 stage3a-20261120-01，基线 mall-crazy-design-20261116 / 9ef118f。评价和本人主动改评均自订单收货时间起算，满 15 天时截止。15 天是项目默认政策，与质量问题售后同口径。未收货仅退款缺少收货依据，有独立中文提示。真实收货后发生退款或关闭订单仍保留资格。

商品分必填，物流分可选，发生售后后才可选填售后分。商品 3 分计入中评。买家针对已冻结且已知的承诺逐项选择符合、不符、没注意，可附说明。服务端从订单项读取模板版本、发布回执和原文。没有快照的旧订单仅保存普通评价。数据库保留原评分兼容列，并同时保存商品分。改评使用预期修订号防止重复提交覆盖，买家可查看原文和历史。商家使用独立评价编号发表站内公开回复。

## 复测记录

资格红测首先复现旧提示“订单未收货或已评价”。初次变更误用了退款表的订单字段，改为按支付记录关联订单后通过。分项红测复现合法分项提交被拒；公开红测复现公开编号等于订单号。隐私复测另发现开票回执返回邮箱，以及旧正文中的号码未脱敏，均在接口修复后由相应测试通过。

首轮服务端全量 490/496，失败涉及旧版直接插入四列、旧隐藏接口预期和昵称契约。保留原有脱敏昵称，将历史隐藏数据与新商家权限分别验证。客户端初轮还受到 pnpm 依赖读取权限限制，使用现有依赖以当前用户权限重跑；原隐藏入口测试已更新为公开回复。

原生构建初次使用默认发布配置，缺少服务地址；调试模式写入既有构建目录时遇到 EPERM。恢复当前用户权限后发现 ArkTS 对草稿与接口参数的结构类型不兼容，改为显式继承。首轮浅色截图中可选评分未即时刷新，修复后重新构建，使用最终签名包从头跑完两种主题。深色商品页沿用的底部“加入购物袋”按钮对比度偏低；本阶段评价区文字、分项结果和操作按钮均已人工读图。

设备使用本地内存夹具和模拟支付，预先准备已发货、已冻结一个版型承诺的订单。验收从本人在应用内确认收货开始，所有评价、改评和公开回复均从普通页面操作。精确评价时间沿用既有显示；商品页的分项均值按当前商品、规格和承诺发布计算。独立正式审核由原 Claude Desktop 会话负责。
