# 阶段 3C 疑似差评登记与独立复核

任务 stage3c-20261120-01，基线 mall-crazy-design-20261116 / d3f75ed。执行方测试结果供原 Claude Desktop Code 会话独立审核。

## 实现与边界

商家从商品评价管理页登记，理由 5 至 200 字，可选择自己已上传的零至三张商品图片。登记写入动作和原文快照，评价仍公开。复核员通过普通账号登录，“我的”页读取服务端授权后显示平台复核入口。服务端每次读取复核队列、受理、给结论时都核对 REVIEW_REVIEWER_ACCOUNTS 中逗号分隔的账号，未配置时无人获授权。商品所属商家和评价对应买家均不能处理本单。

当前评价按整张订单保存。登记时逐项核对 product_changes 中 action=create 的账号。所有商品都属于同一登记商家时开放入口，无法证明归属的历史商品、跨商家订单保留原评价并关闭登记入口。结论支持维持、隐藏、部分更正，部分更正的说明保存在结论理由中。每个动作保存当时的原评价，复核不改写买家的原文。商家和买家可各提一次更正，重新复核期间展示上一份结论。买家不接收催办消息。

## 失败与复验

第一次服务端登记测试返回 404，客户端三条入口测试分别缺登记、平台复核、更正。短理由测试复现两字更正被误拒后修复。第一次读取上传回执时误取 path，测试改走页面实际读取的已上传图片列表。首次全量客户端遇到 pnpm 链接权限及新增按钮缺主题色，随后修正按钮，放行依赖读取并复跑。旧卡片刷新断言同步验证回复及复核状态。Hvigor 首次写现有 loader 缓存遇到 EPERM，获准构建后发现受理空对象未声明类型及买家页声明在导入前，两处已修复并重新签名。设备先跑通两轮，短理由修复后用最终包重新验收。
