# 评价分页优化验收

日期：2026-10-28。范围：现有 GET /goods/:id/evaluate/page 接口。

## 问题与修改

修改前接口读取指定商品的全部评价正文和昵称，逐条转换日期与脱敏，再在应用内截取一页；分页参数也在这些操作之后才校验。隔离数据实测：2000 条评价请求第 7 页、每页 20 条，数据库向应用返回了 2000 条正文；7 种非法分页请求也分别读取了评价后才返回 400。

app.ts 现在先校验商品编号和分页参数，再按同一商品条件计数，并通过 LIMIT/OFFSET 只取当前页；同一订单买了同一商品的多个规格时，EXISTS 条件仍只计一次评价。排序为评价时间降序、订单编号升序，明确同一毫秒下的跨页次序。越界页直接返回空数组，极大合法页码不向 SQLite 传递溢出的偏移量。

响应仍为 code/result，result 包含 items、counts、pages、page、pageSize；每条评价继续只返回原有公开字段和脱敏昵称，未暴露账号、地址、联系方式或订单私有字段。未知商品沿用空结果行为。

## 验证结果

执行 `node --test test/evaluation-pagination.test.ts`（工作目录 server），新增 3 项测试全部通过：

| 检查 | 结果 |
| --- | --- |
| 23 条评价分 5 页读取，同一时间、倒序插入、一单两规格 | 总数 23、无重复或漏项、顺序固定；其他商品仅返回自己的 6 条评价，未评价订单不计入 |
| 2000 条评价请求 20 条 | 修改前实际读入 2000 条，修改后读入 20 条，响应仍为 20 条且总数 2000、页数 100 |
| 非法分页 | 0、负数、小数、非数值页码及不合法每页数量均返回 400，未读取评价正文 |
| 边界和输入 | 空结果、超出末页、Number.MAX_SAFE_INTEGER 页码均保持正确元数据和空数组；SQL 特殊字符不能扩大商品范围 |
| 返回契约 | 日期格式、评分、图片数组和 Unicode 昵称脱敏正确；仅含原有公开字段 |

已运行 `pwsh -File scripts/verify-enterprise-baseline.ps1`，服务端类型检查、55 项服务端测试和 68 项客户端检查通过，合计 123 项；本轮直接改动及调用方审查未发现新增权限或字段泄露问题。

## 证据与边界

代码：server/src/app.ts；回归：server/test/evaluation-pagination.test.ts；原生调用方仍为 features/home 下的 getGoodsEvaluationsAPI，未修改请求或响应结构。

2000→20 是数据库返回到应用的评价正文行数，证明减少了对象创建、日期格式化和昵称处理；不代表 SQLite 只扫描了 20 行，也不等于耗时降低 99%。数据库仍需筛选、计数和排序，深页 OFFSET、相关索引及生产规模耗时留待真实负载评估。固定排序只保证数据不变时跨页一致，翻页期间有新评价时不提供快照一致性。

只操作内存测试库，未变更数据库版本、索引、开发数据或正在运行的服务；未重新构建原生包、未新增设备验收或生产容量证明。商品列表仍存在应用内分页，亲友与商家列表仍返回符合条件的完整数组，这些不是本次已完成项。
