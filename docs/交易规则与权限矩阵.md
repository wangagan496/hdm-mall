| 提醒发货 | 下单人、待发货 | 保持 2 | 仅确认提醒，不当作发货或外部通知已送达 |
| 发货 | 商家、待发货、有有效支付、没有审核中的取消申请 | 2 → 3 待收货 | 第二次返回状态冲突，不重复推进；审核中申请阻止发货，已取消订单提示“买家已取消，不能发货”；当前只记录发货时间，尚无真实运单 |
| 退款执行 | 服务端；商家可对转人工的退款重试 | 退款单：退款中 → 已退款 / 退款失败 | 同一支付最多一条迟到/重复/取消全额退款，售后按申请单独部分退款；所有退款总额不超过支付金额，退回锁定支付的付款人；失败按 1、5、30、60 分钟重试，满 24 小时转人工并通知；启动扫描遇渠道异常记录错误并保留原退款号及后台重试，不阻断服务启动；商家重试带 requestKey，不重复退款 |
| 申请售后 | 下单人、待收货/待评价/已评价、期限内且有剩余可售后数量 | 待收货先在同事务确认收货，其余订单状态保留；新增 pending | 七日无理由从北京时间确认收货次日起算7天，质量/少件从确认收货起15天；同单最多一个进行中；每规格非拒绝/撤回/关闭的累计数量不超过购买数量 |
| 撤回售后 | 下单人、pending或awaiting-return，尚未寄回 | withdrawn | 同号同参回执重放，异参409；撤回释放全部本次申请数量，不退款不入库，保留已同意历史；页面先确认“撤回后需在售后期内重新申请”，returned不能撤回 |
| 同意/拒绝售后 | 商家、pending；退货必须有地址；拒绝原因5–200字 | 退货 awaiting-return；少件 refunding；拒绝 rejected | 48小时自动同意；退货无默认地址保持pending并标红，设置地址立即扫描；首次手动同意保存默认地址 |
| 填寄回单号 | 下单人、awaiting-return，快递公司与单号有效 | returned | 同意后7天未填单号则closed；关闭后仍在申请期内可再次申请；填写后10天未验收自动退款，不入库 |
| 验收/拒绝退款 | 商家、returned；逐规格合格数量0至申请数量；仅无理由可拒绝退款 | refunding 或 refund-rejected | 验收按申请金额退款，只将合格量入库；流水业务键 return:售后ID:规格ID，同事务且只追加；拒绝原因5–200字；事务提交后立即等待本次退款执行，成功更新refunded，失败保留重试，定时扫描兜底；少件同意、48小时自动同意少件及10天自动退款同样即时执行 |
| 支付人工核实 | 商家、已转人工且仍确认中的支付单 | 登记已扣款或未扣款 | 一笔支付只登记一次结果；已扣款必须填扣款时间；可先要求重新查单 |
| 确认收货 | 下单人；或亲友代付订单中当前仍绑定的亲友 | 3 → 4 待评价 | 多人同时操作只成功一次；记录实际收货人；本人付款不授予亲友代收权限 |

## 订单、支付、退款不是同一状态

订单沿用履约状态 1～6。2026-11-06 起支付与退款分开记录（迁移 007）：每次发起支付一条支付单（确认中、成功、失败、已关闭），记录实际付款人、服务端金额和渠道给出的交易时间；每笔需要退回的支付一条退款单（退款中、已退款、退款失败），原因区分迟到成功、重复支付和订单取消。已付款订单的取消申请单独记录（迁移 008），状态为审核中、已撤回、已同意、自动同意、拒绝并发货，每次操作留回执。

订单的有效支付是金额、付款人和交易时间都与订单一致，且没有迟到、重复或取消退款的那一笔成功支付；售后部分退款不使支付失效。售后申请锁定该支付，按申请数量乘下单单价的整数分金额退款，代付订单退回实际付款亲友，不退下单人或受邀但未付款的亲友。

网络超时、回调与查单不一致都对应“支付确认中”，不直接写成失败或取消。

2026-11-09体验审计11–22：订单待确认、收银台、支付结果及亲友卡片采用有总上限的自动只读核对，付款、收货、发货、评价不自动重发；用尽查询预算后保留手动入口。评价必须与本次提交的评分和内容一致才确认本次发布，其他设备的不同评价不冒认。原有第19项取消、撤回、提醒及敏感操作确认保持。地址保存沿同一requestKey递增revision有限重试，资料页返回先保存、失败可保留本机草稿；资料草稿按账号隔离、有效期7日且在下次读取时清理，不含登录凭据。验证记录见《体验审计11-22验收.md》。

已实现并在模拟渠道下验收退货退款、少件仅退款、部分数量退款及逐规格退货验收入库；退款保留订单履约状态及评价资格。质量照片0–3张JPEG、每张不超过512KB，单独登记哈希和上传幂等，只有下单人上传，下单人与商家可读取；照片选择链路尚无设备自动化验收。仍未实现：渠道交易编号、真实渠道验签与商户校验、渠道账单对账、物流签收时间、第七条类商品排除确认、运费补偿与包裹丢失自动处理（后者走客服）。自动退款及少件仅退款不入库。签名包在现有 Pura 90 API24 模拟器以 AfterSaleProbe 连续三次通过，并与 Full、S1、S2、S3、CancelRejectProbe、CancelFamilyProbe、ShipProbe、ProductProbe 同包回归通过，完整结果见《买家测试方案.md》第二十一节。

## 七日无理由退货的法定底线（2026-11-07 核实）

依据三份公开文本：《消费者权益保护法》第二十五条；《网络购买商品七日无理由退货暂行办法》（2017 年原国家工商总局令第 90 号，2020-10-23 市场监管总局令第 31 号修订，以下称“办法”）；《消费者权益保护法实施条例》（国务院令第 778 号，2024-07-01 施行）第十九条。本节只整理条文，不是法律意见；上线前由经营主体按实际商品确认。发货后售后的规则表只能在本节之上补充，不能比它更严。

| 事项 | 法定要求 | 条文 |
| --- | --- | --- |
| 适用 | 网络销售的商品，消费者自收到商品之日起七日内可退货，无需说明理由；七天从签收次日起算 | 消保法第二十五条；办法第二条、第十条 |
| 一律不适用 | 消费者定作的；鲜活易腐的；在线下载或已拆封的音像制品、计算机软件等数字化商品；交付的报纸、期刊 | 消保法第二十五条；办法第六条 |
| 经购买时确认才可不适用 | 拆封后易影响人身安全、健康或品质的；激活或试用后价值贬损较大的；销售时已明示临近保质期或有瑕疵的。必须在下单必经流程中显著确认，不得默认勾选；没有确认就不能拒绝退货 | 办法第七条、第二十条；条例第十九条 |
| 不得扩大范围 | 销售者不能自行增加不适用的商品 | 条例第十九条；办法第三十条 |
| 商品完好 | 为查验拆包装、为确认功能合理调试，不算不完好；超出查验需要使用、价值贬损较大的才算不完好（食品化妆品看一次性密封包装，电子电器看维修、序列号和激活数据，服装家居看标识和污损） | 办法第八条、第九条；条例第十九条 |
| 退货流程 | 收到退货通知后及时提供真实的退货地址、联系人和电话；收到退回商品之日起七日内退款；超过十五日未办理或未退款要受处罚 | 办法第十一条、第十三条、第三十一条 |
| 退款去向与金额 | 比照原支付方式退回，多种方式按各自实付分别退；以实际支出为准；满减中部分退货、不再满足优惠的，按购买时各商品价格多退少补 | 办法第十四条、第十七条 |
| 退货运费 | 默认由消费者承担，另有约定按约定；退货后不再满足包邮条件的，可扣除运费 | 办法第十八条 |
| 退回商品再销售 | 能完全恢复初始状态的可作新品；不能恢复而再次销售的，须显著标注实际情况 | 办法第二十五条 |
| 质量问题 | 不属于无理由退货，另按消保法第二十四条处理 | 办法第三十六条 |
