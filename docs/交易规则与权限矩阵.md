## 状态转换

| 操作 | 操作者与前提 | 状态变化 | 重复、超时与恢复 |
| --- | --- | --- | --- |
| 新建商品 | 商家账号，一级分类有效，规格名称、价格、库存合法 | 新建在售商品及规格、期初库存流水和保存回执 | 一个事务；同账号同 requestKey 同参重放原回执，异参拒绝 |
| 编辑商品 | 商家账号可编辑全部商品；分类只读，只提交变化字段 | 更新商品或规格；绝对库存修改写“商品编辑调整”流水 | 校验 expectedRevision；库存独立校验 expectedStock，冲突带最新内容，保留输入后由用户再次保存；买家下单不使商品版本过期 |
| 上下架 | 商家账号可操作全部商品 | on/off 即时切换；下架从买家列表隐藏，失效购物车行取消勾选 | 只有 status 的请求无需版本比对；同号同参幂等；历史订单价格、付款、发货、退款与库存归还不受影响 |
| 上传商品图 | 商家账号；JPEG 不超过 512KB，请求级限制文件及字段数量 | 先保存图片并登记 image_id，再由商品保存引用 | 上传同号同内容返回原登记；只接受当前账号的登记图，首版不删旧图，备份检查封面及历史订单引用图 |
| 下单 | 已登录、本人地址、规格有效且库存足够；请求带用户看到的应付金额（整数分）和来源（购物车或立即购买）；需确认规则必须由买家主动勾选并携带所见规则的内容版本 | 创建 1 待付款 | 同一账号及 requestKey、相同来源、商品、地址和退货确认内容返回原订单；内容变化拒绝；报价不一致返回 `PRICE_CHANGED`；规则未确认或版本变化返回 `RETURN_POLICY_CONFIRM_REQUIRED` / `RETURN_POLICY_CHANGED` 及新规则，原生清除勾选、更新确认区，不创建订单；库存不足整单不提交；扣库存、订单、明细规则及确认快照同一事务，只有购物车来源删除购物车里的同款；结果不明时按原 requestKey 查询（`/member/order/by-request/:requestKey`），不换号重提 |
| 选择付款人 | 下单人、待付款；亲友须已确认绑定 | 保持 1 | 可选择本人或已绑定亲友；重复选择不增加订单；支付确认中不能更改付款人 |
| 发起支付 | 本人付款模式下的下单人，或指定且仍绑定的亲友；订单待付款且未到付款时限；金额与服务端一致 | 保持 1，新建一条确认中的支付单 | 已有确认中的支付单时拒绝再次付款；付款时限当刻及之后拒绝；渠道未受理则支付单记为失败；宽限截止为发起后 10 分钟 |
| 支付结果确认 | 服务端：验签回调、主动查单或宽限期满关闭后查单 | 宽限期内成功：1 → 2；失败或关闭：支付单结束，订单按时限处理 | 回调须 HMAC 验签且订单、金额与支付单一致，否则拒绝；以查单为准，同一支付单只结算一次；回调与查单相反或成功缺交易时间时保持确认中，连续两次不一致或满 24 小时转人工核实并通知付款人和下单人；迟到成功、重复成功或订单已取消后的成功各自生成一条退款单 |
| 刷新支付结果 | 下单人或该订单的付款人 | 按查单结果 | 同一支付单 5 秒内只查一次；不发起新支付 |
| 模拟付款 | 同“发起支付”，仅测试环境 | 1 → 2 待发货 | 走同一支付单和回调流程，由模拟器给出成功；正式环境禁止启用模拟支付 |
| 取消 | 下单人、待付款（含支付确认中） | 1 → 6 已取消 | 重复取消成功且只归还一次库存；支付确认中取消时同时关闭支付单，之后这笔支付若确认成功，自动退款；亲友不能取消；响应未知先查询；客户端最多 3 次有限重试，只恢复用户已有意图 |
| 到期 | 服务端、待付款且超过 15 分钟，且没有确认中的支付单 | 1 → 6 | 事务内复核状态；有确认中支付单的订单等宽限期结果；已付款不释放库存；多次扫描不重复释放 |
| 申请取消 | 下单人、已付款待发货、有有效支付、没有审核中的申请 | 保持 2，新建审核中申请，截止 72 小时 | 同一 requestKey 同参重放返回原回执、异参拒绝；同单最多一个审核中申请；已发货提示联系售后；申请不退款、不释放库存 |
| 撤回申请 | 下单人、申请审核中且未到截止 | 保持 2 | 不限撤回再申请次数，每次新申请重新计 72 小时；到截止后撤回按自动同意处理并提示 |
| 同意取消 | 商家；或服务端在 72 小时截止时自动同意 | 2 → 6 已取消 | 与库存释放（每个规格一次，记入库存流水）、有效支付的退款单、申请结束同一事务；提交后立即等待执行本次退款，失败仍按原计划重试；有效支付与申请锁定的支付不一致时拒绝；启动及每30秒扫描保留作兜底 |
| 拒绝取消并发货 | 商家、申请审核中；原因必填，最多 200 字 | 2 → 3 待收货 | 原因与发货同一事务；不退款、不释放库存；发货后不能再申请取消 |
| 提醒发货 | 下单人、待发货 | 保持 2 | 仅确认提醒，不当作发货或外部通知已送达 |
| 发货 | 商家、待发货、有有效支付、没有审核中的取消申请 | 2 → 3 待收货 | 第二次返回状态冲突，不重复推进；审核中申请阻止发货，已取消订单提示“买家已取消，不能发货”；当前只记录发货时间，尚无真实运单 |
| 退款执行 | 服务端；商家可对转人工的退款重试 | 退款单：退款中 → 已退款 / 退款失败 | 同一支付最多一条迟到/重复/取消全额退款，售后按申请单独部分退款；所有退款总额不超过支付金额，退回锁定支付的付款人；渠道 15 秒未响应先记为退款中，按 1、5、30、60 分钟间隔重试；满 24 小时转人工并通知；沿用原退款编号，迟到成功与重试保持幂等；启动扫描遇渠道异常保留后台重试、不阻断服务启动；商家重试带 requestKey，不重复退款 |
| 申请售后 | 下单人、待收货/待评价/已评价、期限内且有剩余可售后数量；逐规格按下单规则和确认快照校验类型 | 待收货先在同事务确认收货，其余订单状态保留；新增 pending | 七日无理由从北京时间确认收货次日起算7天，质量/少件从确认收货起15天；已确认拆封/激活类保留无理由入口，须逐项声明未拆封/未激活或试用（`conditionDeclared=sealed`）；已拆封/激活不能提交无理由，临期/瑕疵已确认及法定排除不能选无理由，未确认的需确认类按标准规则；质量和少件不受退货限制影响；同单最多一个进行中，每规格累计数量不超购买数量 |
| 撤回售后 | 下单人、pending或awaiting-return，尚未寄回 | withdrawn | 同号同参回执重放，异参409；撤回释放全部本次申请数量，不退款不入库，保留已同意历史；页面先确认“撤回后需在售后期内重新申请”，returned不能撤回 |
| 同意/拒绝售后 | 商家、pending；退货必须有地址；拒绝原因5–200字 | 退货 awaiting-return；少件 refunding；拒绝 rejected | 48小时自动同意；退货无默认地址保持pending并标红，设置地址立即扫描；首次手动同意保存默认地址 |
| 填寄回单号 | 下单人、awaiting-return，快递公司与单号有效 | returned | 同意后7天未填单号则closed；关闭后仍在申请期内可再次申请；填写后10天未验收自动退款，不入库 |
| 验收/拒绝退款 | 商家、returned；逐规格合格数量0至申请数量；仅无理由可拒绝退款 | refunding 或 refund-rejected | 验收按申请金额退款，只将合格量入库；流水业务键 return:售后ID:规格ID，同事务且只追加；拒绝原因5–200字；事务提交后立即等待本次退款执行，成功更新refunded，失败保留重试，定时扫描兜底；少件同意、48小时自动同意少件及10天自动退款同样即时执行 |
| 支付人工核实 | 商家、已转人工且仍确认中的支付单 | 登记已扣款或未扣款 | 一笔支付只登记一次结果；已扣款必须填扣款时间；可先要求重新查单 |
| 确认收货 | 下单人；或亲友代付订单中当前仍绑定的亲友 | 3 → 4 待评价 | 多人同时操作只成功一次；记录实际收货人；本人付款不授予亲友代收权限 |
| 评价 | 下单人、已收货且未评价；文字通过敏感词校验 | 4 → 5 已评价 | 一单一评；重复提交拒绝；响应未知先查询同一评分及内容且未被隐藏，确认一致才清本地草稿 |
| 登记开票信息 | 下单本人结算时选填；或完成收货后在订单详情补登记 | 无 → requested，不改变交易状态 | 个人/单位抬头、接收邮箱；单位必填税号。发票由商家线下开具，开具后会在订单中标记；同参登记幂等，已开票不能覆盖 |
| 标记已开票 | 商家，有已登记的开票信息 | requested → issued，不改变交易状态 | 发票号码选填；同请求号重试不重复处理，结果未知保留原编号；买家本人可见状态及号码 |
| 隐藏评价、重置头像 | 商家，必须选择广告、辱骂、无关内容、泄露隐私或其他原因 | 评价转为隐藏，不在商品页公开；头像变为默认 | 买家可见隐藏原因或头像通知，可修改后重新发布或重新上传；不改变订单、付款和退款历史 |

| 客服留言与回复 | 买家本人一个会话；商家从客服列表进入回复；关联订单必须是本人订单 | 新消息增加对方待回复/未读状态 | 文字1–500字，买家可附0–3张JPEG；同号同参幂等，已读只推进到已加载的消息；注销冷静期仍可留言、上传照片和标记已读 |

## 关键操作审计（2026-11-10，迁移014）

商品新建、名称/说明/图片变动、上下架、规格价格/启用/库存变化、库存盘点、发货、拒绝取消并发货、同意取消、售后处理、验收入库、退款创建/结果/重试、付款人工核实和退货地址变更均记录操作人、时间、对象与结果；自动处理的操作人为“系统自动”。金额以整数分保存，界面显示元；改价和库存明确前后值，验收按规格列出合格入库数量。

审计与业务改动共用事务，任一写入失败整体回滚；请求回执重放不重复记账。数据库触发器禁止修改和删除审计行。非商家访问商家接口返回403时另开小事务记录拒绝，同账号、同接口模板一分钟内只记录一次，不保存查询参数或请求正文。

summary 采用字段白名单，不复制密码、凭据、买家地址、电话、图片路径或请求全文；商品说明/图片及退货地址只记“已修改”，原因文本隐藏号码、凭据标签和图片链接。退款对象通过原付款人外键查询账号，注销后显示“已注销用户”，不保留旧账号快照。

只有商家可通过“我的 → 操作记录”查看，支持全部、商品与价格、库存、发货、售后与退款、访问拒绝分类；商品编辑和商家订单详情可进入该对象的记录。API 支持操作类型、订单、商品、操作人、起止毫秒时间戳筛选，时间和自增编号倒序分页；点击记录进入对应商品或商家订单详情。商家详情使用独立商家接口，原买家订单参与权限不变。

迁移从现有商品回执、库存调整、取消/售后动作、退款重试及支付核实补录可确认事实，并标为历史记录；无法确认的修改前内容不推测，历史普通发货明确“历史数据，未记录操作人”，拒绝取消并发货不再重复补普通发货。迁移只执行一次，不改原回执。版本14备份检查审计对象、操作人、摘要白名单及只追加触发器，旧版本2–13仍沿用原检查规则。

## 订单、支付、退款不是同一状态

订单沿用履约状态 1～6。2026-11-06 起支付与退款分开记录（迁移 007）：每次发起支付一条支付单（确认中、成功、失败、已关闭），记录实际付款人、服务端金额和渠道给出的交易时间；每笔需要退回的支付一条退款单（退款中、已退款、退款失败），原因区分迟到成功、重复支付和订单取消。已付款订单的取消申请单独记录（迁移 008），状态为审核中、已撤回、已同意、自动同意、拒绝并发货，每次操作留回执。

订单的有效支付是金额、付款人和交易时间都与订单一致，且没有迟到、重复或取消退款的那一笔成功支付；售后部分退款不使支付失效。售后申请锁定该支付，按申请数量乘下单单价的整数分金额退款，代付订单退回实际付款亲友，不退下单人或受邀但未付款的亲友。

网络超时、回调与查单不一致都对应“支付确认中”，不直接写成失败或取消。

2026-11-09体验审计11–22：订单待确认、收银台、支付结果及亲友卡片采用有总上限的自动只读核对，付款、收货、发货、评价不自动重发；用尽查询预算后保留手动入口。评价必须与本次提交的评分和内容一致才确认本次发布，其他设备的不同评价不冒认。原有第19项取消、撤回、提醒及敏感操作确认保持。地址保存沿同一requestKey递增revision有限重试，资料页返回先保存、失败可保留本机草稿；资料草稿按账号隔离、有效期7日且在下次读取时清理，不含登录凭据。验证记录见《体验审计11-22验收.md》。

已实现并在模拟渠道下验收退货退款、少件仅退款、部分数量退款及逐规格退货验收入库；退款保留订单履约状态及评价资格。质量照片0–3张JPEG、每张不超过512KB，单独登记哈希和上传幂等，只有下单人上传，下单人与商家可读取；照片选择链路尚无设备自动化验收。仍未实现：渠道交易编号、真实渠道验签与商户校验、渠道账单对账、物流签收时间、第七条类商品排除确认、运费补偿与包裹丢失自动处理（后者走客服）。自动退款及少件仅退款不入库。签名包在现有 Pura 90 API24 模拟器以 AfterSaleProbe 连续三次通过，并与 Full、S1、S2、S3、CancelRejectProbe、CancelFamilyProbe、ShipProbe、ProductProbe 同包回归通过，完整结果见《买家测试方案.md》第二十一节。

## 七日无理由退货的法定底线（2026-11-07 核实）

依据三份公开文本：《消费者权益保护法》第二十五条；《网络购买商品七日无理由退货暂行办法》（2017 年原国家工商总局令第 90 号，2020-10-23 市场监管总局令第 31 号修订，以下称“办法”）；《消费者权益保护法实施条例》（国务院令第 778 号，2024-07-01 施行）第十九条。本节只整理条文，不是法律意见；上线前由经营主体按实际商品确认。发货后售后的规则表只能在本节之上补充，不能比它更严。

| 事项 | 法定要求 | 条文 |
| --- | --- | --- |
| 适用 | 网络销售的商品，消费者自收到商品之日起七日内可退货，无需说明理由；七天从签收次日起算 | 消保法第二十五条；办法第二条、第十条 |
| 一律不适用 | 消费者定作的；鲜活易腐的；在线下载或已拆封的音像制品、计算机软件等数字化商品；交付的报纸、期刊 | 消保法第二十五条；办法第六条 |
| 经购买时确认才可不适用 | 拆封后易影响人身安全、健康或品质的；激活或试用后价值贬损较大的；销售时已明示临近保质期或有瑕疵的。必须在下单必经流程中显著确认，不得默认勾选；没有确认就不能拒绝退货 | 办法第七条、第二十条；条例第十九条 |
| 不得扩大范围 | 销售者不能自行增加不适用的商品 | 条例第十九条；办法第三十条 |
| 商品完好 | 为查验拆包装、为确认功能合理调试，不算不完好；超出查验需要使用、价值贬损较大的才算不完好（食品化妆品看一次性密封包装，电子电器看维修、序列号和激活数据，服装家居看标识和污损） | 办法第八条、第九条；条例第十九条 |
| 退货流程 | 收到退货通知后及时提供真实的退货地址、联系人和电话；收到退回商品之日起七日内退款；超过十五日未办理或未退款要受处罚 | 办法第十一条、第十三条、第三十一条 |
| 退款去向与金额 | 比照原支付方式退回，多种方式按各自实付分别退；以实际支出为准；满减中部分退货、不再满足优惠的，按购买时各商品价格多退少补 | 办法第十四条、第十七条 |
| 退货运费 | 默认由消费者承担，另有约定按约定；退货后不再满足包邮条件的，可扣除运费 | 办法第十八条 |
| 退回商品再销售 | 能完全恢复初始状态的可作新品；不能恢复而再次销售的，须显著标注实际情况 | 办法第二十五条 |
| 质量问题 | 不属于无理由退货，另按消保法第二十四条处理 | 办法第三十六条 |

对本项目的要求与当前实现：

- 已实现固定规则选择：`standard` 默认支持；`law-excluded` 仅定作、鲜活易腐、数字化、报刊四类；`confirm-required` 仅拆封、激活或试用、临近保质期、已明示瑕疵四类。瑕疵说明5–100字，不允许自增例外。原生详情、购物车按原因显示白话，结算逐件显著说明，默认不勾选；只有法定排除商品时不要求勾选。修改走商品版本校验及 `product.return_policy` 审计，只影响新订单。
- 已实现明细规则、原因、说明及主动确认快照。预结算返回 `returnPolicyToken`（规则内容版本，不是登录凭证），创建请求带 `returnPolicyConfirmed` 与 `expectedReturnPolicyToken`；规则变更要求重新确认，幂等恢复沿原订单。拆封/激活类不能把“已确认规则”当作“已拆封/激活”：买家逐项如实声明、未拆封或未激活可申请，商家验收显示原声明；临期和已明示瑕疵在确认后排除无理由，其他质量问题仍可申请；未确认的需确认类与迁移前旧订单按标准规则。服务端逐SKU校验，原生混合申请明确排除不适用行且允许切换类型；质量与少件不受影响。
- 当前以买家确认收货时间及北京时间次日计算七日无理由期限，质量和少件15天；物流签收时间仍待接入。待收货申请前显示“提交后视为已收到货”，提交与收货同事务。
- 退款已按锁定的有效支付退回实际付款人；申请48小时未处理自动同意，寄回后10天未验收自动退款为项目兜底，不能替代法定的实际收到退回商品后7日内退款要求；物流未接入时由商家及时验收。
- 本项目约定退货运费由商家承担；寄回同表单填写实付运费和运单截图，验收只将合格数量入库，0允许，损坏数量不自动补回；2026-11-11实现与验收边界见A包记录。
