# 客户端环境配置与发布校验

范围：原生商城与内嵌资料网页的服务地址、旧演示订单开关及构建检查；不配置真实支付，不部署服务，不迁移开发数据。

## 构建配置

`mixed-development-h5/build-support/client-environment.ts` 负责校验，项目根 `hvigorfile.ts` 将同一组字段注入当前 product 的所有模块，`GlobalVariable.ets` 从生成的 `BuildProfile` 读取；不再通过修改业务源码切换地址。

| 变量 | development | test | production |
| --- | --- | --- | --- |
| `HDM_APP_ENV` | debug 未指定时默认 | 必须显式指定 | release 未指定时默认；release 禁止其他环境 |
| `HDM_API_BASE_URL` | 默认 `http://127.0.0.1:3000`，允许覆盖 | 必填，可使用隔离测试地址 | 必填，HTTPS 域名原点 |
| `HDM_DECISION_SERVICE_URL` | 默认 `http://10.0.2.2:8765`，空字符串关闭 | 未指定则关闭 | 未指定则关闭；启用时必须为 HTTPS 域名原点 |
| `HDM_DEMO_ORDER_FLOW` | 默认 false，可显式设置 true | 只允许 false | 只允许 false |

地址只允许服务原点，例如协议、主机和可选端口，不接受路径、查询、片段、凭证、空白或反斜线；production 拒绝 IP 字面量、单标签主机、本机和内网常见域名后缀及示例域名，错误仅显示变量名，不回显误填的秘密。此处检查字符串格式，不能证明域名解析、证书、服务归属、网络可达性或生产服务已验收。

变量取自构建进程环境，原生端不自动读取 `.env`；IDE 需继承相应环境后启动。脚本使用独立 Hvigor 进程，避免常驻构建进程保留旧环境。签名配置继续使用既有本机文件，环境切换不改动签名材料。

## 使用入口

开发默认保持本机调试地址和关闭演示订单流程：

```powershell
pwsh -File scripts/verify-project.ps1 -BuildMode debug
```

测试环境使用 debug 构建，并显式提供测试服务原点；生产构建使用 release，先在启动构建的终端配置 `HDM_API_BASE_URL` 为实际受控的 HTTPS 服务原点，需要智能分流时再配置 `HDM_DECISION_SERVICE_URL`，然后运行：

```powershell
pwsh -File scripts/verify-project.ps1 -BuildMode release
```

release 验证禁止 `-SkipH5`、`-SkipNative`，必须重新构建网页并完成原生打包；正式 API 地址缺失、本机地址、非 HTTPS 地址、开发环境或演示开关开启时均拒绝构建。直接运行 Hvigor 或 IDE 的 release 同样执行原生配置校验；直接 IDE 构建仍须先执行 `pnpm run build:mobile` 更新网页资源，不能把旧网页文件当作本轮源码构建证据。

## 网页地址与凭证

`pnpm run build:mobile` 的网页通过原生 `getApiBaseUrl()` 使用同一个服务地址，禁止设置 `VITE_API_BASE_URL`；原生桥存在时，即使旧网页配置了其他地址，也优先采用原生地址。地址缺失或原生桥返回空值时，在发送请求及读取登录凭证前失败，不回退到本机服务。

独立网页开发保留本机调试默认地址；独立网页正式构建要求显式配置 `VITE_API_BASE_URL` 为 HTTPS 域名原点。`VITE_` 变量会进入网页产物，不得存放密钥。智能分流未配置时不会发出网络请求，页面沿用原有不可用提示。

## 复跑检查

```powershell
node --test scripts/tests/client-environment.test.mjs
pwsh -File scripts/verify-enterprise-baseline.ps1
pwsh -File scripts/verify-client-environment.ps1
```

最后一个脚本实际调用 Hvigor 验证四类错误配置，随后使用仅供编译检查的虚构域名完成 release 构建、核对生成字段与 H5，再恢复默认 debug 包并还原进程环境；测试域名不作为真实部署地址，不向该域名发送业务请求。日志位于临时目录 `hdm-client-environment-check`，构建不等于生产签名、设备或真实服务验收。
