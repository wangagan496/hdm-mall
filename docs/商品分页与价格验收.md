# 商品分页、排序与价格验收

验收日期：2026-10-29。

## 问题与结果

搜索、猜你喜欢及热门接口原先先读入全部可售商品，再在应用内筛选、排序和分页。隔离测试建立 1001 件商品（其中 1 件售罄），另有 4 件初始化商品：搜索匹配 1000 件、请求 20 件时，修复前读入 1004 件商品正文，修复后只读入当前页 20 件。非法分页参数原先可能先触发正文查询，现在先验证参数。

商品详情原先会把售罄规格纳入最低价：测试中 0.01 元规格售罄、10 元规格有货时，列表显示 10 元而详情显示 0.01 元；现在两处均显示可购买规格最低价 10 元。全部规格售罄时列表隐藏该商品，已打开的详情仍保留历史最低价，库存为 0、规格禁用。

## 实现范围

| 入口 | 当前处理 |
| --- | --- |
| POST /search/all | 数据库完成关键词、父子分类筛选、排序、计数与分页，保留 result.pageData |
| GET /home/goods/guessLike | 数据库计数和分页，保留原分页响应 |
| GET /hot/:type | 数据库计数和分页，保留 subTypes[].goodsItems |
| GET /goods | 展示有货规格最低价，保留规格各自价格与库存 |

catalog.ts 的 listPage 使用同一筛选条件执行 COUNT 与 LIMIT/OFFSET；超出总数直接返回空页，避免极大页码导致偏移量溢出。参数使用绑定值，排序只由固定选项生成。关键词继续区分大小写，百分号、下划线和单引号按字面量匹配，分类保留当前子类或其直接父类的含义。

服务端商品编号排序统一使用 SQLite BINARY，原生 searchPresentation.ets 与 SearchResultView.ets 按 Unicode 码点比较，避免系统语言影响同价商品顺序。价格排序同价时按编号升序；销量目前全部为 0，仍以编号升序兜底；publishTime 仍沿用编号排序，并非实际上架时间。现有 hdm-* 编号顺序保持一致，大小写、标点或非 ASCII 编号可能与旧 localeCompare 的语言排序不同，这是统一两端次序的明确取舍。

首页及分类的旧完整数组接口仍返回完整数组，仅复用数据库筛选和排序，尚未改成分页；本次不改变其响应契约。

## 验收边界与剩余项

本次证明减少了向应用返回及转换的商品正文行数；COUNT、GROUP BY 与排序仍可能扫描数据，不能据此声称数据库扫描或响应耗时降低 99%。索引、深页、生产数据规模和并发负载仍需独立测量。千件商品分页由接口及原生逻辑交叉测试验证，模拟器仅验证现有 4 件商品的公开浏览流程，没有执行千件商品滚动压力测试。

本轮不变更数据库版本 5，不执行迁移、部署或真实资金操作；模拟器检查不能替代真机或 Hypium 验收。首页和分类完整数组、关系列表、旧数组接口退役及真实销量和上架时间仍是后续事项。
