# 首页图片预加载设备验收

日期：2026-10-28。

结论：API 23 的缓存预加载在 Pura 90 API24 模拟器上实际生效；确认了下载成功、跨应用进程重启复用、下拉刷新复用、异步 HTTP 失败不阻塞首页和恢复显示。此次是指定图片的功能验收，不是实体真机或整页性能基准。

## 范围与方法

- 工程仍使用 `6.1.1(24)`，没有升级 API 26。
- 安装当前应用，使用本地开发后端的真实首页与 ArkUI Image；未使用替代平台依赖的 Node 模拟测试。
- 在本机临时代理中，仅给轮播图片网址添加唯一 `preloadProbe` 查询参数，绕开历史缓存；图片内容仍为后端原来的 308 字节 SVG。
- 同时记录实际 HTTP 请求和设备日志。临时观测仅对测试网址增加 `cacheDownload` 成功／失败订阅及 Image 完成／失败日志，不增加等待，不改变 LAZY 策略。
- 暖缓存检查时让测试图片的网络地址返回 503，而首页数据接口继续正常响应；随后重启应用和下拉刷新，核对是否还请求该图片、是否仍能显示。
- 失败检查使用另一个此前未缓存的网址，避免旧缓存遮住真实失败；没有清空账号、数据库或整份应用缓存。

## 实测结果

| 场景 | 证据 | 结果 |
| --- | --- | --- |
| 首次访问新图片网址 | 收到 START、SUCCESS 和 IMAGE_COMPLETE；图片服务器实际收到 1 次 GET，200，308 字节 | 通过 |
| 重启应用后复用 | 应用进程从 8080 变为 8592；图片网络端已设置为 503，但新增图片请求为 0，仍收到 SUCCESS 和 IMAGE_COMPLETE，截图可见图片 | 通过 |
| 下拉刷新复用 | 首页数据接口再次收到请求，设备再次记录 START／SUCCESS；图片 GET 总数仍为 1 | 通过 |
| 未缓存图片返回 503 | 服务器实际收到 503 请求；系统回调返回 `errorCode: 48, message: "503"`，Image 同时报错；首页分类、商品和底部导航仍显示，应用进程未退出 | 通过；失败图片本身不能正常加载 |
| 失败后操作与恢复 | 可以点击分类页，再返回首页刷新；恢复有效网址后收到 SUCCESS／IMAGE_COMPLETE，图片重新显示 | 通过 |

在添加临时观测之前，原应用也已完成一次冷／暖检查：首次图片请求 1 次，重新启动后新增 0 次，截图仍显示轮播图。
