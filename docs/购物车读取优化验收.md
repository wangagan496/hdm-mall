# 购物车读取优化验收

验收日期：2026-10-29。

## 目标

购物车读取原先先查询购物车行，再为每个 SKU 单独查询规格和商品资料；购物车商品越多，数据库查询次数越多。

## 改动

`server/src/catalog.ts` 的 `cart()` 现在通过购物车、规格和商品表的一次 JOIN 查询返回完整资料，并按购物车行顺序稳定返回。价格、库存、规格名称、勾选状态和图片地址的返回字段保持原契约；加购和修改购物车仍沿用原有库存校验。

## 验证

`server/test/optimization.test.ts` 构造 3 个购物车商品，确认返回数量和规格顺序，并统计到只执行 1 次购物车 JOIN、0 次逐 SKU 规格查询。

角标接口 `/member/cart/count` 此前仍调用完整购物车读取再求和；本轮改为 `Catalog.cartCount()` 在数据库按当前用户汇总件数，只返回一个数量。外键保证购物车关联的规格和商品存在，无需为计数联查商品表；包含未勾选和售罄条目，空车返回 0，响应继续使用 `{ code: '1', result: { count } }`。

新增接口回归先在旧实现复现读取 3 条明细，改动后明细读取为 0；两种规格数量 2 与 3 返回 5，另一用户返回 7，匿名返回 401，清空本人购物车后返回 0。已核对鉴权、绑定用户参数和件数语义；没有改变库存或过期处理路径。

购物车修改入口补充：`PUT /member/cart/:id` 现在按本人和指定 SKU 读取修改后的单项，返回字段与原接口一致；`PUT /member/cart/selected` 更新后直接返回 null。复用现有 JOIN 与字段转换，没有复制商品组装逻辑。

新增两项接口回归先在旧实现失败：三件商品修改一件仍读入 3 行，连续两次全选读取两次整车；修复后分别只读 1 行和不读取明细。已验证完整单项回应、只改勾选时保留数量、超库存返回 409 且原数量保留、他人没有的条目返回 404、另一账号相同规格的数量及勾选状态不变；局部审查核对了用户与 SKU 绑定参数及全列表调用默认行为。

完整基线 `pwsh -File scripts/verify-enterprise-baseline.ps1` 通过：服务端 TypeScript 检查、73 项服务端测试和 82 项客户端检查全部通过，0 失败、0 跳过，共 155 项。

本轮未做生产容量、响应耗时或真实设备购物车性能测量，也未部署或迁移开发数据。

## 原生购物车勾选与数量修复（2026-10-29）

沿购物车修改调用链发现原生请求与接口契约不符：全选额外发送 `count: 0` 导致 400；单件取消勾选携带旧数量，售罄后被库存校验拒绝为 409；修改数量携带旧勾选值，覆盖服务端较新的选择。`UpdateCartParams` 的两项改为可选，`CartOperations.ets` 各入口只提交本次修改字段，服务端校验保持不变。

`CartView.ets` 全选改为保存成功后才更新列表勾选及金额，失败保留原混合勾选并提示重试；用同一个处理中标记阻止勾选、数量和全选并发修改，并拦截处理期间的删除与结算，相关商品及结算控件禁用。全选回应晚到时核对账号及列表引用，已刷新列表继续采用服务端结果，不把旧操作回写到新列表或新账号。

`scripts/tests/cart-selection.test.mjs` 新增 7 项检查：三项执行实际原生业务方法和 API 封装并连接内存后端真实路由，先复现 400、409 和覆盖勾选，修复后全部通过；四项提取实际页面方法，覆盖保存前金额不变、成功更新、失败保留及重试、重复操作与提前结算拦截、单件保存期间互斥，以及刷新和换账号后的晚到回应。页面四项同样先失败后通过。平台 UI 与角标边界使用替身，不视为设备验收。

最终完整基线通过：服务端类型检查、73 项服务端和 89 项客户端检查，共 162 项，0 失败、0 跳过；`pwsh -File scripts/verify-optimization-build.ps1 -SkipH5` 原生增量构建和签名通过，2026-10-29 15:32:38 的签名包为 3,620,159 字节，包内 H5 与现有网页产物哈希一致。本轮未重建 H5，未执行设备、Hypium、真实支付或生产容量验收。

## 购物车列表异步查询修复（2026-10-29）

源码审查发现列表查询存在两个直接问题：`loadCartList()` 没有请求编号和账号校验，旧账号或旧页面的迟到成功、失败都可能覆盖当前列表；任意刷新失败还会把已有商品清空。`getCartListAPI()` 现使用发起时的固定 token，避免请求期间借用后来登录的账号。

页面现在按请求编号、页面生命周期、账号 token 三项确认后才接收结果；换账号立即清除旧购物车并重新查询，退出页面或重新进入后旧请求不能结束新查询。刷新失败保留当前商品、勾选和金额，显示刷新失败入口；保留商品在失败态禁止勾选、改数、全选、删除和结算，重试成功后恢复这些操作。账号资料变化但 token 未变时不重复读取购物车。

`scripts/tests/cart-loading.test.mjs` 新增 8 项检查，覆盖乱序成功／失败、刷新失败保留、换账号、退出重进、固定凭证、账号监听、旧写操作回应及失败态操作限制，其中 6 项查询检查先失败后通过，2 项关联操作检查在修复后加入并通过。与购物车勾选专项合计 15 项测试，自动基线为 73 项服务端与 97 项客户端，共 170 项，0 失败、0 跳过；原生增量构建及签名通过，2026-10-29 15:47:30 产物 3,621,930 字节，包内 H5 哈希校验通过。本轮仍未做真机、Hypium、生产容量或真实支付验收。
