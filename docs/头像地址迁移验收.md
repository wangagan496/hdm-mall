# 头像地址迁移验收

日期：2026-10-28；范围为现有头像上传、登录与资料接口，以及数据库和图片备份恢复。

## 问题与修复

原实现把 PUBLIC_URL 和文件路径一起存进账号资料；已复现将数据库及头像恢复到新目录、配置新域名后，登录仍返回旧域名头像。上传测试也确认数据库保存的是完整地址。

当前新头像只保存 `/uploads/<UUID>.jpg`，Accounts 在登录、资料读取及资料保存回应中按配置生成完整地址，上传回应继续返回完整地址，保持客户端接口契约；地址不取自 Host 或转发域名，不能由请求头改变。

版本 5 在独立事务中将旧的规范 HTTP/HTTPS UUID JPEG 引用转换为相对路径，保留其他资料及库存流水；不猜测转换外部图片、携带凭据或查询参数、路径跳转或编码地址，不发起远程下载。此识别规则沿用项目上传及备份的本地文件约定，不能用于把任意外部图片当作本地文件。

迁移全部成功才修改版本号；坏 JSON 等失败会回滚已转换的资料和版本，关闭连接，修正数据后可重新启动。旧版本程序会拒绝打开版本 5，回退需要匹配程序的旧快照，不能只修改版本号。

备份兼容版本 2、3、4、5，同时识别新相对引用和旧规范绝对引用，仍只复制快照引用的不可变图片；不支持的头像继续使备份失败。恢复只写新目录，原备份字节保持不变。

## 部署边界与复用方法

本轮只使用临时数据库和测试图片，未重启现有开发服务、未迁移开发库或切换生产域名；客户端源码未改，本轮未重新构建原生包或执行真机验证。服务端接口继续返回完整地址，客户端缓存的旧地址需重新读取资料或登录后更新；本修复不自动配置 CDN，也不负责迁移图片文件，数据库与 uploads 仍须一起恢复。

修复文件地址可迁移性时，先用旧备份和新配置复现，再把稳定的文件引用与环境地址分开；同时验证上传回应、登录、资料保存、备份文件集合和失败回滚，避免只改显示地址却漏掉历史数据或恢复流程；这一方法已在当前 UUID JPEG 头像约定下验证。
