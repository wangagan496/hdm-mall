# 首页分类、亲友分页与断网恢复验收

验收日期：2026-10-29。

## 已解决的问题

首页新品、推荐此前从旧数组接口读取全部商品；推荐虽逐次增加 limit，后端并未应用该参数。分类接口还把每个父类和子类的全部商品重复带回，但分类卡片只使用编号、名称及封面。亲友中心和付款页也一次读取全部关系，再由付款页筛选可代付亲友。

本轮新增兼容式入口并切换原生调用：

| 入口 | 当前行为 |
| --- | --- |
| GET /home/new/page | 数据库计数和分页，原生新品区只请求首批 8 件 |
| GET /home/recommend/page | 原生每次请求真实页码、固定 8 件，按服务端 pages 判断结束 |
| GET /category/summary | 一次查询生成分类编号、名称、封面及子类，不附带商品正文；隐藏无可售子类的分类 |
| GET /member/relations/page | 默认返回本人发起或收到的未撤销关系，每页 10 条，创建时间降序、编号升序固定次序 |
| 同上，scope=payer | 先筛选本人发起且已确认的关系，再计数和分页，供付款页选择代付人 |

旧 /home/new、/home/recommend、/home/category/head、/category/top 和 /member/relations 数组接口保留兼容；新版原生对应入口已经切换，不把旧接口仍存在误记为旧客户端已经退役。

首页推荐继续排除首屏和已展示商品，重复整页继续向后查询；请求或图片处理失败不推进页码，重试不跳页。刷新或离页后拒绝旧请求及迟到图片回写，旧请求也不能提前释放新请求的加载锁。下拉刷新全断网时保留原首屏商品，修复了原先清空商品的问题。

亲友关系、亲友订单和发货订单各自保存页码；解除末页最后一个关系后回到新的最后一页。付款页仅展示服务端确认的可代付关系，关系加载失败有明确提示和重试入口，保留原列表并禁止点击过时的邀请按钮。读取固定使用发起时会话，换账号或离页后不回写旧数据。

## 设备验收

在 API 24、1320×2856、深色模式的 Pura 90 模拟器上，scripts/device-trade-regression.ps1 -RelationsProbe 已通过，使用独立内存后端准备 11 位已绑定亲友：

1. 设备实际下单进入付款页，翻到第 2 页并邀请 probe_00 代付；后端确认 invitedPayerAccount 为 probe_00。
2. 亲友中心翻到第 2 页，解除唯一的 probe_00 关系；页面自动返回第 1 页，后端确认剩余 10 条关系、1 页。

4. 强制停止并重新启动应用，仍显示 device_buyer 登录状态，重新进入亲友中心可读取最新的 10 条关系。
