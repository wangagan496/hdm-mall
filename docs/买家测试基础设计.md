# 买家测试基础设计

本步只实现 D1、D10 和 L1—L3 门禁，支付状态机与渠道结果由 D2 实现。

## 时钟
buildApp 增加可选 clock: Clock（now(): number，Unix 毫秒），默认 systemClock 读取真实时间；同一对象传给 Accounts、Catalog、Orders 和库存流水/调整函数，订单创建、到期、支付、发货、收货、评价、会话及亲友关系均从它读时间。返回上下文中的 clock 供之后的支付模拟器共用。测试推进 clock 后经真实接口触发到期检查，无需等待；生产保留原有定时扫描。客户端保持开机时间语义，native-harness 替换系统 getUptime 边界，执行真实倒计时和收银页代码，不复制计算公式。

## 数据与权限
buildApp 增加 testMode 和 testFixtures: { credential }，只有显式 testMode=true、非 production 且凭证至少 32 字符时启用；配置先校验再打开数据库，默认不注册夹具路由。启用时不运行内置商品 seed。
同一夹具服务提供 account、address、product（包含多个规格、分单位价格、初始库存及期初流水）、relation 函数；account 支持 buyer/merchant，关系通过真实邀请/确认逻辑创建。直接函数与 /__test/fixtures/{accounts,addresses,products,relations} 都校验独立凭证，HTTP 使用 X-Test-Fixture-Key；普通 Bearer 买家凭证无效。每条测试独立数据库与凭证、显式自建所需商品，不共享结果。支付结果预设只在设计中保留 presetPayment(clock, paymentId, outcome) 扩展位置，本步不注册假成功接口。
server/test/helpers/fixtures.ts 提供 buildTestApp 与自建商品快捷函数；真机内存夹具复用同一服务，脚本从夹具元数据读取规格、价格、库存，不依赖种子编号。

## 执行与验收
新增 buyer-tests CI 任务，Node 24.16.0、安装 server 与 H5 的锁定依赖（native-harness 使用 H5 TypeScript），运行 npm run check、npm test、node --test scripts/tests/对应文件；H5 原任务原样保留。L1—L3 必须零失败、零跳过；本机执行 verify-enterprise-baseline.ps1。Node 24.16.0 支持 --test-randomize 与 --test-random-seed，CI 每次额外随机运行服务端测试并记录种子，本机可按种子重现顺序。L4 本步不运行，生产配置拒启、买家越权、时间边界和数据隔离均有自动化断言。
