## 学习者情况与教法要求

- 刚开始学读源码，ArkTS/TypeScript 语法基础弱；业务直觉不错，常能提出合理的产品和优化想法。
- 每题只贴要考的 2-5 行源码，逐行配白话注释；不要整段贴函数。
- 题干里不能提前给出答案或关键术语，只给场景让学习者判断（学习者多次指出“你都说出来了”）。
- 一次只问一个问题；答错时说清哪里错、为什么，再出下一题。
- 用大白话，少用术语；必须用术语时当场解释（例如 `Date.now()` 讲成“读手机时钟”）。
- 学习者觉得源码难懂时，会要求改代码可读性：按业务步骤拆方法、起看得懂的名字、补中文注释，改完要跑原生构建和单元测试。
- 讨论出的优化想法，学习者确认后记入 `docs/优化记录.md`，写明当前情况、优化点、解决的问题、验证要点，标记“待实施”。

## 已讲过的主要模块

2026-10-28 阶段判断：核心业务模块及鸿蒙/H5 跨端链路的第一轮概览已完成，后续十块模块见文末记录；模块依赖与统一存储、数据库订单快照和表关系也已补讲。用户最新确认本阶段收尾，不再追加必学模块或以独立编码、测试、排错为结课条件；讲过、情境答对、助手协助完成与独立实现仍分别记录，既有薄弱点仅供以后按需复习，不据此把已完成的概览重新标成未完成。

### 1. 应用入口与导航
`PhoneAbility.ets`、`Index.ets`、`TabConstants.ets`：启动时恢复登录、预取首页；底部 Tabs 管栏目切换，`NavPathStack` 管子页面前进返回。

### 2. 商品浏览与搜索
`HomeView.ets` → `SearchView.ets` → `SearchResultView.ets` → `GoodsView.ets`：
- 页面名常量（`PagePath.ets`）要和 `router_map.json` 登记的名字一致；传参的数据名（`keyword`）发送方和接收方要对应。
- 先保存关键词再查询；`await` 等待；`loading` 在 `finally` 里关闭；换关键词先清空列表，翻页才追加。
- 用 `queryGeneration` 编号丢弃旧请求结果；改排序要换编号，翻页不换。
- 分页按商品编号去重，不能按名称；详情页要重新取最新数据；兜底 SKU 只用于展示，不能加入购物车。

### 3. 购物车到创建订单
`AuthCart.ets`、`CartOperations.ets`、`CartView.ets`、`CheckView.ets`、`server/src/orders.ts`：
- 加购要 `await` 结果，刷新角标不必等；改数量先等服务器成功再更新页面。
- 连续点击应合并成最终数量、一次只发一个请求；数量没同步完不能去结算。
- “去结算”只展示确认信息，“立即支付”才创建订单；`requestKey` 实现幂等，防止重试生成两笔订单。

### 4. 支付结果、取消与库存
`PayResultView.ets`、`orders.ts`：
- 支付后以服务端查回的状态为准；查询失败显示“待确认”，不能显示“未付款”。
- 并发支付/取消：“检查状态→更新状态”要作为整体执行（事务），不能把所有订单排成一队。
- 取消与归还库存放在同一个事务里；重复取消不重复归还库存；结果未知时提示“暂时无法确认”。
- 服务端必须核对金额和请求方身份，不能信任手机端传来的值。

### 5. 订单列表（第一轮已讲，细节待巩固）
`OrderView.ets`、`OrderTabLoader.ets`、`OrderPresentation.ets`、`OrderCountdown.ets`：
- 手机端再筛一次：去掉已取消订单、移出状态已变的订单。
- 合并时同一订单号后放的覆盖先放的（留最新状态）；时间相同再比订单号，保证顺序稳定。
- 筛完不满一屏继续取下一页；是否取完只看服务端；`nextPage` 记下次从第几页取。
- `isFinished` 挡住取完后的请求，刷新时必须重置为 `false`；`loading` 保证同一时间只有一个加载请求。
- 倒计时按“读手机时钟 − 拿到订单时间”计算，不是每秒减 1；改手机时间会影响显示，但不影响服务端判断。
- 组件消失时要清掉定时器；订单操作成功后要重新向服务端取，手机上的副本不会自己变。
- 用一张“按订单号记录”的表可以只锁正在处理的订单；从表里删除必须放在 `finally`。

## 薄弱点（需要多练）

- 读赋值、条件、循环语句时，常把变量含义或执行顺序弄反（例如并发时两次请求都读到同一页码、把手机时钟拨快后的结果算反）。
- 容易把“现象”当“原因”，或把不同的表混在一起（把“正在处理的表”当成存订单状态的表）。
- 结论方向常常对，但后果说得不准（例如说成“缓存积攒、打不开 App”，实际是定时器空转越用越卡）。
